- A new or edited bash script that the built-in parser rejects is now checked with `bash -n` before AFT calls it broken. Valid scripts the parser can't read, such as an escaped `[ "$a" \< "$b" ]` comparison, are no longer reported as "does not parse", and valid edits to them are no longer rolled back. For a confirmed error, the reply names the line bash reports. When bash can't give a verdict (no bash, which is always the case on Windows, a timeout, or another failure), the reply says the syntax check is unknown (`bash_unavailable`, `bash_timeout` or `bash_failed`).
- Syntax errors in new files now point at the line where parsing actually got stuck, not at the first line of a larger block the parser gave up on.
