Runon jobs now use durable submission keys when the executor advertises support. If a stream loses its outcome, AFT can re-attach to the same job and resume after its saved output cursor instead of leaving the result unknown. Recovery is bounded by three retries, the run timeout, and the executor's 24-hour key retention. Executors without submission-key support keep the previous behavior. A refusal of a retry does not replace the original job ID, so the original job remains identifiable for cancellation.
