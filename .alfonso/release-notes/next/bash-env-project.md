- `bash.env` now has a project tier. `<project>/.cortexkit/aft.jsonc` may set `bash.env` names, and AFT applies them to local shell commands only while that project is on the filter trust list (`aft doctor filters trust`); a linked worktree inherits its main checkout's trust. A user value wins when both tiers set the same name, and the first bash reply in a session names each applied variable with its tier. Untrusting a project stops its values on the next command, without a reload.
- A harness block's `bash.env` now merges its names into that tier's base map instead of replacing the whole map. Previously, adding one name under `harnesses.pi` silently dropped every base name.
- `bash.env` values no longer reach a `runon` build-server job unless the user lists the name in the new user-only `bash.runon_env` array. A project's values are never sent. Every `bash.env` name that is not sent appears in the job's "the remote job does not receive: …" disclosure.
- The list of names `bash.env` refuses is wider and now applies at both tiers: startup hooks, lookup roots (`HOME`, `TMPDIR`, `XDG_*`, `CARGO_HOME`, …), interpreter injectors, Git redirection and `GIT_CONFIG*`, AFT and module controls (`AFT_*`, `SUBC_*`, …), and sandbox and build-slot controls (compile wrappers, `RUST_TEST_THREADS`/`NEXTEST_TEST_THREADS`, `SCCACHE_*`). Credentials, identity, proxy, and TLS-trust names are refused from project config only. A refused name rejects the config file with an error naming the key; matching is case-insensitive on every platform. Configurations that already used `AFT_*`-prefixed or thread-count names must move them to per-call `env` (per-call names are still checked against the list) or remove them.
