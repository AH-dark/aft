# AFT 0.60.0 (unreleased)

## Changed

- AFT declares call modes through subc-protocol 0.31: classic keeps every existing tool, codemode serves the head catalog with direct-call parity, and flow serves only `read`, `grep`, `glob`, `aft_search`, `aft_outline`, `aft_zoom` and `aft_callgraph`. Codemode bash refuses background and PTY work, clamps its timeout to the run deadline (refusing a missing deadline), and kills its process group once the run scope is confirmed ended. Flow refuses shell, writes and `aft_inspect` as `call_mode_unsupported`; inspect can execute repository build scripts. Unknown modes are also refused as `call_mode_unsupported`.

- Views: an incremental call-graph update could store a different result than a full build when two references in a file shared an ordinal. The materialization version moves from 9 to 10, so every view rebuilds its call graph once, on its next publication after upgrading.

## Storage

- `aft.db` moves to schema 16, which adds the `access_scopes`, `access_grants`, `access_launch_params` and `access_materialized` tables for permission grants. An older AFT refuses a schema-16 database. To roll back past this release, stop AFT, then in one transaction drop those four tables and set `schema_version` to 15.

- Storage retention reclaims checkout view folders (`views/<scope>`) faster. Caches whose checkout is gone and past its grace (24 hours for a deleted linked worktree, 7 days for any other checkout, including a linked worktree whose binding was recorded before 0.59) are now cleaned on the next pass, instead of waiting for the walk over every cache to reach them, which could take about two days. A view folder that no family registry lists and no binding records is removed once it has gone an hour without being observed or changed, if nothing pins it, reads it or locks it. Before, it waited a week. If a registry or another needed fact cannot be read, the folder is kept and counted under `skipped_unknown`. A binding record written by a release before 0.59, which did not record whether its checkout was a linked worktree, is now upgraded while its checkout still exists. The inspect projection lookup no longer creates an empty view folder for a checkout that has none. Each pass report adds `due_keys` (keys past their grace that still have caches; a key identifies one checkout's caches, or the caches shared by one repository), `due_first` (what the pass examined, skipped and removed for those keys before the walk resumed), `orphan_views` (the same counts for orphan view folders), `skipped_unknown` and `upgraded_bindings`.
